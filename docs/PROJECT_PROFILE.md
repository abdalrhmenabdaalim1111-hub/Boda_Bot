### Dependency policy
The project deliberately ships **minimal third-party dependencies**. The Control Center
does **not** introduce a web framework. The single new dependency allowed is
`cryptography` (Fernet) for token encryption at rest — there is no stdlib AEAD —
and the code degrades gracefully (tokens stay in `.env`, masked in the UI) when it
is not installed, so every Windows launcher keeps working.

## 2. Approved Decisions

| ID   | Decision | Rationale |
|------|----------|-----------|
| **D1** | **Keep SQLite.** Add a reversible migration runner; never hand-edit schema. | Existing DB holds live data (users, sessions). Zero-risk continuity. |
| **D2** | **Zero new web-framework dependencies.** Extend `api_server.py` in place (stdlib only): `ThreadingHTTPServer` + router registry + SSE + hand-written OpenAPI 3.1 at `/openapi.json`. | Owner decision. Project style is stdlib-first. |
| **D3** | **Backward compatibility is mandatory.** Every existing route, the `run_api_server()` / `start_api_thread()` contract, and the existing test suite stay green at every phase boundary. | Owner rule. |
| **D4** | **`bots_registry.json` stays the single source of truth** for the bot catalogue. The DB gains a *mirror* table (`bot_config`) for runtime config, joins and analytics — it does not replace the registry. | The registry is read by the store bot, the mini-app generator and the Tkinter manager. |
| **D5** | **New bots are built on the existing `bot_base` + `prepare_bot()` stack** (telebot). No new bot framework, no new base class. | Consistency with 34 existing bots. |
| **D6** | **`Data/ads_config.json` and `Data/monetag_config.json` remain the legacy read path.** The new ad library lives in SQLite; the JSON files are kept in sync as a mirror so old readers and existing ad tests keep passing. | Avoids breaking `ad_manager`, `ad_watcher`, `Manager.py`, `tools/build_mini_apps.py`. |
| **D7** | **`tools/build_mini_apps.py` must stop destroying `webroot/`.** It becomes marker-aware so agent-authored ad blocks survive rebuilds. | Root cause blocker for the whole Ads phase (risk R2). |
| **D8** | **Work on branch `feature/control-center`**, small logical commits, no force-push, timestamped backup before every migration or file write. | Owner rule. |
| **D9** | **The Control Center DB is the same SQLite file** as the bots use (`Data/boda_bot.db`, overridable via `BODA_DB_PATH`). | One database → joins are trivial, no second source of truth, no cross-DB sync. |
| **D10** | **The supervisor owns bot processes as child processes** (one process per bot), and refuses to start a bot that is already owned by a running `server_runner.py`. | "Picks up new code on restart" requires a fresh process; avoids Telegram polling conflicts. |

## 4. Process Model — three parallel implementations exist today

| # | Implementation | Model | Notes |
|---|----------------|-------|-------|
| 1 | `Manager.py` (Tkinter) | one `subprocess.Popen` per bot | Windows-first; auto-restart after 5 s |
| 2 | `StartManager.py` (console) | one `subprocess.Popen` per bot | older duplicate, not imported by `Manager.py` |
| 3 | `server_runner.py` (headless, production) | all bots as **threads in one process** | polling with backoff 5 s→300 s, or shared webhook server |

`bot_base.prepare_bot()` is the single wiring point that attaches, in order:
`ad_manager.attach_unified_ads` → `growth_engine.attach_growth_engine` →
`unified_middleware.install_unified_layer`.

The Control Center introduces **one** shared supervisor (`control_center/supervisor.py`)
and re-points #1 and #2 at it in a later phase, without breaking either launcher.

## 6. Known Landmines — do not break these

1. `tools/build_mini_apps.py:366` runs `shutil.rmtree(webroot)` — every rebuild
   wipes any manual or agent-authored edit. Must become marker-aware (D7).
2. There are **zero** ad marker blocks in the codebase today. The only static ad
   artifact is the Monetag loader `<script src=…>` in `tools/app_template.py:330`;
   the banner and sponsor are created client-side by the AdSDK
   (`tools/app_template.py:195-239`).
3. `api_server.py` uses a **single-threaded** `HTTPServer` — SSE would block every
   other request. Must become `ThreadingHTTPServer`.
4. `Manager.py:241` calls `re.search` but never imports `re` → the token-from-code
   fallback always raises a swallowed `NameError`.
5. `tools/secret_scan.py` raises `UnicodeEncodeError` on a cp1252 console when
   printing Arabic (fine in CI/Linux, fails locally on Windows).
6. `Data/events.jsonl` is unbounded append-only JSONL — no rotation, no DB backing.
7. `Bots_Folder/database.py` creates `ab_ad_stats` twice (harmless, `IF NOT EXISTS`)
   and one Arabic comment line is corrupted to `????`.
8. `Data/bots_audit.json` (36 entries) is an **orphan artifact** — nothing writes it.
